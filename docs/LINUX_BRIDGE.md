# Linux bridge — implemented candidate

One exporter JAR bundles JeroMQ 0.6.0 and jnacl/license notices; Bookmap APIs remain compile-only. No second acquisition plugin or divergent market schema exists. Network code runs on the publisher thread, with DONTWAIT sends, ROUTER/DEALER data and REP/REQ health. Defaults: bridge disabled, bind 0.0.0.0, market TCP 5555, health TCP 5556, unacknowledged capacity 100,000; window 256, socket HWM 512. Use unique port pairs for simultaneous instruments. No auth/TLS exists: restrict enabled endpoints to a trusted private LAN/firewall. Owner tokens are continuity identifiers, not credentials.

The first owner begins with HELLO seq 0 and receives WELCOME plus START-derived events. ACKs remove retained events only up to validated seq. Same-owner HELLO replays the bounded in-flight window; marked retained duplicates are checked rather than treated as new events. A send failure pauses delivery and retains data; handover supports reconnect before old pipe removal. Lack of activity for two seconds marks DISCONNECTED. Overflow/invalid ACK/different owner invalidates completeness, clears/counts retained backlog and counts later dropped offers. A missing receiver is not repaired by relabeling data HEALTHY.

HISTORY offer waits for capacity for up to ten seconds per stalled wait; before REALTIME_START the backlog drains with a ten-second deadline. In responsive LIVE, optional bridge offers never wait for ACKs; overload invalidates the bridge and the journal remains independent. Historical optional bridge waiting can slow extraction even though the archive is separate. Startup/bind errors and parser exceptions are observable but exceptional cleanup/snapshot concerns are open issues.

Private receiver responsibilities: validate schema/session/seq/market clock/IDs/pips/book before ACK, preserve MBO state through same-process reconnect, expose HEALTHY/INVALID/DISCONNECTED/STOPPED, and reject new publisher sessions after accepted events. Only a receiver with zero accepted events may re-arm for a different healthy WELCOME after a stale invalid publisher. Neither side implements durable spool, snapshots, resume-after-process-restart, fan-out subscribers or execution logic.

Startup: close Bookmap; install only the correct exporter JAR; start the private receiver against the Windows IP; open Bookmap and enable/apply bridge if necessary for a fresh START. Avoid applying again to a healthy running session. Restart a receiver with accepted events before a new publisher session. The private `tools/linux/Start-Receiver.sh` discovers local LAN/health; explicit `--host WINDOWS_IP` is supported. This script is private and not supplied by the public repository.

Windows smoke: extract the bundle with JAR/BAT/PS1/README together, run BAT. It finds Java 17+ (Bookmap runtime, JAVA_HOME, PATH, common installations), prints LAN addresses, probes health and checks stable session/ACK progression/error counters over 60s. PASS requires progress, not an idle market; INCONCLUSIVE means insufficient activity. It never binds ports or registers another market receiver. A PowerShell helper double-click may close immediately; use BAT. Health alone does not establish receiver host identity or finalized archive correctness.
