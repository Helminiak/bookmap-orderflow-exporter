## Scope and limits of approval

Approval covers the tested v0.4 canonical acquisition/archive integrity, default 60-second checkpoint configuration, finalized byte accounting, and clean shutdown. The complete run includes the history/live transition and records periodic checkpoints. It is not a blanket certificate for all feeds, instruments, replay rewind behavior, long-running production capture, abrupt crash/power-loss durability, or physical disk wear. Peak queue utilization and quiet-versus-busy write timelines are absent from the supplied evidence, so no sustained queue-latency or disk-activity claim is made. The approval relies on the complete 786,347-record run rather than inferring stream integrity from summary counters alone.

## Validation code update

Previously the public script's exit status checked JSON parsing and sequence gaps only, even when time reversals or inconsistent MBO state were observed. It could not compare the finalized stream with the writer summary. The updated validator fails closed on canonical schema/lifecycle, timestamps, MBO identity/state inconsistencies, invalid execution markers, malformed gzip and summary mismatch. It accepts `--summary` to check pips, writer status, record/event/timestamp/order counts and v0.4 buffering/byte-accounting fields. Capture-only and uncompressed NDJSON invocation remain available; pips/summary checks are explicitly marked as not performed when absent. The stricter healthy-capture policy rejects rewound/anomalous/partial streams rather than silently approving them.

```sh
python tools/validate_export.py /external/capture.ndjson.gz --summary /external/capture.summary.json
python -m unittest discover -s tests -v
```

Thirteen synthetic regression tests cover healthy captures, prior-version summaries, exact opaque IDs and execution boundaries, tied timestamps, malformed JSON/fields, sequence/time errors, duplicate/unknown MBO changes, inconsistent cancellation state, gzip CRC/truncation/deflate failures, writer/summary/pips/byte mismatches, missing STOP and correct nonzero failure exit status. Hosted CI runs these tests and packages the unchanged v0.4 JAR on Windows and Ubuntu. Raw captures remain local and are never CI inputs or uploaded artifacts.
