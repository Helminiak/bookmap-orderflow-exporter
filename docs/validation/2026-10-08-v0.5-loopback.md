## Synthetic publisher loopback

Linux localhost, JDK 17, Python 3.12, JeroMQ 0.6.0/pyzmq 27.2.0. Each run generated 190,003 synthetic records (1,000 cycles). Capacity 100,000 unacknowledged events, window 256, socket HWM 512. Baseline target 5,000/s is a chosen test rate, not a measured ES peak. No Bookmap application or physical Windows/Ubuntu LAN was used.

All runs observed zero seq gaps/duplicates/time reversals in the validated prefix. The 50× run is **INVALID**, despite zero observed seq gaps: publisher overflow discarded the bounded unacknowledged backlog and health reported loss of completeness. The producer continued to its full 190,003 generated records. This is the intended overload response; it is not a complete-delivery success.

Publisher rate includes handshake and final health-observation grace; receiver rate spans first-to-last received batches. Short rate/queue results vary with JVM warmup, scheduling and batch timing; these single trials are not maximum sustained capacity guarantees. Standalone fixture callback timing covers construction/offer after JSON was prepared, not full exporter callbacks.

Sampled peak receiver RSS was 38.8–42.1 MiB, publisher RSS 349–426 MiB. The publisher fixture retains its generated synthetic journal strings for exact comparison; that memory is not the production queue size. Each run's CPU seconds and sampled RSS are in the attached aggregate JSON. No CPU percentage or Bookmap slowdown is inferred.

## Actual exporter callbacks, without Bookmap

The real addon callback fixture generated 190,003 records; all 190,003 reached the receiver. Target input rate 100,000 events/s; observed receive interval rate 68,419/s. The gzip journal passed CRC/schema/seq/lifecycle/book checks and ended with 60,000 open orders, matching the summary. Bridge/journal overflows and receiver gaps/duplicates were zero. Bridge high water 4,193; journal high water 2,676. Final compressed synthetic journal 2,783,282 bytes.

Callback histogram: count 380,002, mean 0.170 µs, p50 ≤0.064 µs, p95 ≤0.512 µs, p99 ≤2.048 µs, max 5.419 ms. Count includes timestamps and market callbacks, excludes initialize/stop. Log2 quantiles are bucket upper bounds; measured duration excludes histogram bookkeeping. No Swing panel was shown. Outliers can include JVM/OS scheduling and warmup.

These timings are synthetic callback invocation, not the <3% Bookmap slowdown acceptance test. Callback paths contain no transport/socket/disk/compression waits in responsive LIVE mode. Historical journal backpressure is intentionally different.

## Known capture and failure tests

The local validated v0.4 capture replayed through the private receiver validator: 786,347 records, 332,003 ADD, 57,882 REPLACE, 323,552 CANCEL, 72,907 TRADE, 3 controls; final 8,451 open orders and zero sequence/MBO/time failures, matching the supplied summary. Gzip read to EOF verified CRC/ISIZE. Capture data stays local; only aggregate results are recorded here.

Injected skipped sequence and unmarked duplicate → INVALID. Capacity-one overflow → publisher/receiver INVALID. New receiver process → INVALID until a fresh exporter session. Same receiver disconnect/reconnect → complete deterministic 573-record sequence with retransmit handling and zero gaps. Bind/config failure leaves journal independent. No network failure was allowed to wait a market callback.
